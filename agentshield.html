The problem

Agents act on what they read. Attackers write what they read.

01

Agents now hold real credentials: GitHub tokens, database keys, email, payments, a shell.

02

An LLM has no separation between control and data. Your instruction and every tool result share one context window.

03

Text planted in an issue, ticket or web page can steer the agent: indirect prompt injection, a confused-deputy attack.

04

The weak point is the missing checkpoint between what the agent decides and what it does.

Real incident  /  Invariant Labs  /  26 May 2025

One public issue leaked private repositories.

Invariant Labs showed that the official GitHub MCP server let a single public issue pull a user's private repositories into a public pull request. The agent ran Claude 4 Opus, one of the most safety-trained models available. It still complied.

SETUPA public repo anyone can file issues on, plus private repos. One token reads and writes both.
INJECTIONAn attacker opens an issue with instructions aimed at "the author's agent".
TRIGGERThe user asks for something ordinary: "have a look at the open issues".
IMPACTPrivate project names, relocation plans, even salary, published in a PR.

No bug to patch: every call was within the token's rights. What was missing is a check that asks did the user ask for this, and where did this data come from?

"This is not a flaw in the GitHub MCP server code itself, but rather a fundamental architectural issue that must be addressed at the agent system level."

    The idea

    Three checks. None of them trusts the model.

    01

    Intent contracts

    Before the agent reads anything untrusted, the user's request is compiled into a signed, frozen list of allowed actions. Injected text cannot widen it.

    FIXES: hand-written policies, and policy LLMs attackers target mid-task
    02

    Argument provenance

    Every value in a tool call is traced to who wrote it and who may see it, through base64, hex, homoglyphs and spelled-out text. Secrets cannot reach a public sink.

    FIXES: the open problem named in 2026 research; detectors that can be reworded around
    03

    Risk-adaptive causal check

    Only for high-risk calls the rules cannot settle, replay the step with the user's task masked. If the action survives, the content it read is driving it.

    FIXES: MELON-style checks that double the cost of every step

    HONEST LIMITSThe replay measures the shield, not a model. The contract comes from a planner that reads only the user instruction. The causal check relies on MELON's premise. 9 of 63 adaptive variants succeed, all documented (e.g. a paraphrased leak inside an allowed action). AgentDojo workspace and travel suites not yet run.
